# Internationalisation (i18n)

Library: `next-intl` v4. Locales: `de` (default, unprefixed URLs such as `/spielplan`) and `en` (`/en/spielplan`).
Slugs are identical in every language (`localePrefix: "as-needed"`, no `pathnames` map).

## Layout

```
i18n/routing.ts      locales, default, LOCALE_TAGS (Intl), OG_LOCALES, LOCALE_LABELS
i18n/navigation.ts   Link, redirect, usePathname, useRouter, getPathname (locale-aware)
i18n/request.ts      per-request locale + messages + timeZone
i18n/messages.ts     AREAS registry — one JSON file per area
proxy.ts             locale negotiation (matcher excludes api, studio, og, llms.txt)
messages/<locale>/<area>.json   UI strings; de/ is the source of truth and types the keys (global.d.ts)
lib/i18n/format.ts   dateFormatter / currencyFormatter / compareText (locale + CLUB_TIME_ZONE)
scripts/check-i18n.mjs          `npm run i18n:check`: same keys + same {placeholders} in every locale
```

## Rules

1. **Links:** import `Link`, `redirect`, `usePathname`, `useRouter` from `@/i18n/navigation`, never from `next/link` / `next/navigation` (except `notFound`, `useSearchParams`, `useParams`). Plain `<a href="/…">` to internal pages also becomes `Link`. External links, `mailto:` and `/api/...` URLs stay as they are.
2. **Server components:** `const t = await getTranslations("namespace")`. **Client components and sync server components:** `useTranslations("namespace")`.
3. **Pages and layouts** under `app/[locale]` take `params: Promise<{ locale: string }>`, call `setRequestLocale(locale)` first (keeps pages statically rendered / ISR) and use `getTranslations({ locale, namespace })` in `generateMetadata`.
4. **Namespace = top-level key** inside the area file, named after the component or page (`header`, `footer`, `spielplanFilters`). Keys are camelCase, grouped by meaning, not by the German wording. Plurals and counts use ICU (`{count, plural, one {# Spiel} other {# Spiele}}`), never string concatenation.
5. **Rich text** (bold, links inside a sentence): `t.rich("key", { b: (chunks) => <strong>{chunks}</strong> })`.
6. **Dates / numbers / sorting:** no hardcoded `"de-DE"` or `"de"`. Get the tag with `LOCALE_TAGS[useLocale() as Locale]` (or `getLocale()`) and build formatters through `lib/i18n/format.ts` (keeps `timeZone: CLUB_TIME_ZONE`). Module-level formatter constants become functions or `useMemo` keyed on the locale. Day-keys that are data (e.g. `en-CA` for `YYYY-MM-DD`) stay as they are.
7. **Not translated:** people and team names, nuLiga data (league names, referee names, venue names), CMS content (Sanity) until the schemas are localized, brand names, legal texts (`impressum`, `datenschutz`; these show a short note on English pages).
8. **`aria-label`, `alt`, `title`, `placeholder`, metadata, JSON-LD descriptions and `confirm`/error texts are user-visible**: translate them too.
9. **English style:** British English, sentence case, short and direct, handball terms: Spielplan = "fixtures", Ergebnisse = "results", Tabelle = "table"/"standings", Heimspiel = "home game", Auswärtsspiel = "away game", Kader = "squad", Trainer = "coach", Förderverein = "supporters' association (Förderverein)", Spieltagsmagazin = "matchday magazine", Halle = "sports hall", Jugend = "youth", Herren/Damen = "men"/"women".
10. After editing, `npm run i18n:check` and `npx tsc --noEmit` must pass.

## Adding a language

1. Add the code to `LOCALES`, `LOCALE_LABELS`, `LOCALE_TAGS`, `OG_LOCALES` in `i18n/routing.ts`.
2. Copy `messages/de/` to `messages/<code>/` and translate; run `npm run i18n:check`.
3. Add the language to the Sanity localized fields (once those exist) and to the sitemap config.
